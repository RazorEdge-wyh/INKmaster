## 1. 项目概述

INKmaster 是一个 **AI 驱动的中文网络小说创作平台**，核心功能是通过九步创作流水线（世界观→力量体系→故事大纲→主要角色→冲突引擎→次要角色→爽点节奏→细纲规划→物品道具），利用 AI 大模型自动生成小说设定和正文。

**核心能力**：
- 九步创作流水线生成完整小说设定
- 章节批量生成（SSE 流式输出）
- 15 种网文类型模板（玄幻、修仙、都市、恐怖、科幻等）
- 多 AI 供应商支持（DeepSeek、OpenAI、Anthropic Claude、Ollama）
- API Key 加密存储（Fernet 对称加密）
- 小说导出（TXT / JSON）
- Token 用量统计
- 真相文件管理（故事一致性维护）
- 原生桌面应用（pywebview + Edge WebView2）

**项目来源**：INKmaster 是一款 AI 驱动的小说创作平台，后端采用 FastAPI + SQLAlchemy 异步架构，前端为 React SPA（已编译为静态文件交付）。

## 4. 核心架构详解

### 4.1 启动流程

```
run_gui.py
  ├── 1. _find_free_port() — 找空闲端口（动态分配，不固定 8000）
  ├── 2. daemon 线程启动 FastAPI（uvicorn.run）
  │     └── app/main.py → lifespan → init_db() 创建 SQLite 表
  │                     → 启动 _periodic_session_cleanup() 定时任务（每30分钟）
  ├── 3. _wait_for_server() — 轮询 /health 直到后端就绪（最多 20 秒）
  │     ├── GET、超时 1.5s、间隔 0.25s、总超时 20s
  └── 4. pywebview 打开原生窗口
        ├── 成功：title="INKmaster — AI 小说创作平台", url=url, 1400x900, min 960x600
        │   ├── try: webview.start(gui="edgechromium", debug=False)
        │   └── except: webview.start(debug=False) — WebView2 不可用时回退
        └── 失败：title="INKmaster — 启动失败", 红色错误页 HTML, 480x280
              └── sys.exit(1)
```

**模块级逻辑**（run_gui.py）：
- frozen 环境将 stdout/stderr 重定向到 exe 旁 `data/logs/inkmaster.log`（try/except pass）
- 设置 `UVICORN_LOG_LEVEL=warning` 并将 uvicorn 三个 logger 静音为 WARNING
- uvicorn 日志级别设为 WARNING，GUI 模式不刷屏

**关键细节**：
- 端口是动态分配的，config.py 里的 `port: int = 8000` 是默认值，实际被 run_gui.py 覆盖
- 日志输出到 `data/logs/inkmaster.log`（仅打包环境）

### 4.3 数据库连接 database.py

```python
"""Async SQLAlchemy engine and session management."""
```

**核心组件**：
1. `engine` — `create_async_engine(settings.database_url, echo=False, connect_args={"check_same_thread": False})`
2. `_enable_sqlite_foreign_keys` — SQLite 事件监听器，连接时执行 `PRAGMA foreign_keys=ON`（**必须**，否则 ON DELETE CASCADE 不生效）
3. `async_session` — `async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)`
4. `get_db()` — FastAPI 依赖，async 生成器：
   - `async with async_session() as session` → `yield`
   - 成功：`await session.commit()`
   - 异常：`await session.rollback()` + `raise`
   - finally：`await session.close()`
5. `init_db()` — 函数内 `from app.models.base import Base`，`async with engine.begin()` + `run_sync(Base.metadata.create_all)`

### 4.4 安全模块 security.py

```python
"""API Key 加密工具。使用 Fernet 对称加密保护存储的 API Key。"""
```

**密钥加载优先级**（`_load_key()`）：
1. `settings.encryption_key`（环境变量/.env 显式指定）
2. 本地密钥文件 `DATA_DIR / ".inkmaster.key"`
3. 自动生成 `Fernet.generate_key()` 并写入文件

**核心函数**：
- `encrypt(plaintext: str) -> str` — 加密明文字符串，空串原样返回
- `decrypt(token: str) -> str` — 解密；对历史遗留的明文存储做容错（解密失败时原样返回）

**设计要点**：
- 模块级 `_cipher = Fernet(_load_key())` 单例
- 兼容旧数据：旧版本明文存储的 API Key 在 decrypt 时会原样返回，不会报错

### 4.5 AI 供应商层 ai/

**架构**：策略模式 + 工厂模式

#### base.py — 抽象基类

```python
@dataclass
class GenerationParams:
    temperature: float = 0.7
    max_tokens: int = 4096
    top_p: float = 1.0
    frequency_penalty: float = 0.0
    presence_penalty: float = 0.0
    extra: dict = field(default_factory=dict)  # 未使用

@dataclass
class ModelResponse:
    content: str
    prompt_tokens: int = 0
    completion_tokens: int = 0
    model: str = ""

class BaseProvider(ABC):
    def __init__(self, api_key: str, model: str, api_base: str | None = None)
    @abstractmethod async generate(system_prompt, user_prompt, params=None) -> ModelResponse
    @abstractmethod async stream_generate(system_prompt, user_prompt, params=None) -> AsyncIterator[str]
    @abstractmethod async validate_connection() -> tuple[bool, str]
    async close(self)  # 关闭底层 HTTP client
```

#### factory.py — 工厂模式

```python
_registry = {
    "openai": OpenAIProvider,
    "deepseek": OpenAIProvider,   # DeepSeek 用 OpenAI 兼容接口
    "ollama": OpenAIProvider,     # Ollama 也用 OpenAI 兼容接口
    "anthropic": AnthropicProvider,
}

class ProviderFactory:
    @classmethod register(name, provider_cls)
    @classmethod create(provider, api_key, model, api_base=None) -> BaseProvider
        # 未知供应商抛 ValueError，f-string 提示可用项
    @classmethod list_providers() -> list[str]
```

#### openai_provider.py — OpenAI 兼容供应商

- `__init__`：创建 `AsyncOpenAI(api_key, base_url=api_base or None, timeout=300.0, max_retries=2)`
- `generate()`：3 次重试 + `asyncio.sleep(2 ** attempt)` 指数退避，`attempt >= 2` 时重抛；usage 为 None 时 token 数取 0
- `stream_generate()`：`stream=True` 创建后 `async for chunk in stream`，过滤 `chunk.choices[0].delta.content` 后 `yield`，流完成后 `return`
- `validate_connection()`：发送 `("Say hello.", "Hi!")`、`max_tokens=10` 测试，成功返回 `f"连接成功 (模型: {model})"`
- `close()`：`await self.client.close()`

#### anthropic_provider.py — Anthropic Claude

- 客户端为 `AsyncAnthropic`
- `generate`：用 `messages.create(model, system, messages, temperature, max_tokens)` 并遍历 `response.content` 拼接 `block.type == "text"` 的块，token 取 `usage.input_tokens/output_tokens`
- `stream_generate`：用 `async with client.messages.stream(...) as stream` + `async for text in stream.text_stream`
- **关键细节**：`return` 在 `async with` 块外、try 块内（已验证）

### 4.6 九步创作引擎 engine/

#### state.py — 流水线状态管理

**枚举与数据类**：
- `StepStatus(str, Enum)`：`pending / running / completed / failed / skipped`
- `@dataclass PipelineStep`：`key, number, name, description, is_critical, estimated_time` + 运行时字段（`status, result_text, streamed_text, error, started_at, completed_at`）
- `@dataclass StepResult`：`step_number, status, raw_output, parsed_data, error`
- `@dataclass GenerationSession`：`session_id, book_id, title, concept, word_count, mode` + `steps/results/context_log` 三个字典
  - `create(cls, session_id, book_id, title, concept, word_count, mode="auto")` — classmethod
  - `_init_steps()` — 内置 9 步定义
  - `get_previous_context(up_to_step) -> str` — 获取前序上下文
  - `touch()` — 更新最后访问时间
- `PIPELINE_STEPS_DEF` — 九步骨架静态定义（供 orchestrator 与 API 层共用）

**九步定义**：

| 步骤 | key | 名称 | 关键性 | 预估时间 |
|------|-----|------|--------|----------|
| 1 | `world_setting` | 世界观构建 | ✅ 关键 | ~45s |
| 2 | `power_system` | 成长力量体系 | 可选 | ~35s |
| 3 | `outline` | 故事大纲 | ✅ 关键 | ~60s |
| 4 | `main_characters` | 主要角色 | ✅ 关键 | ~60s |
| 5 | `conflict_engine` | 冲突引擎 | 可选 | ~40s |
| 6 | `supporting_characters` | 次要角色 | 可选 | ~55s |
| 7 | `plot_rhythm` | 爽点与节奏规划 | 可选 | ~40s |
| 8 | `detailed_outline` | 细纲规划 | ✅ 关键 | ~90s |
| 9 | `items` | 物品与道具 | 可选 | ~30s |

**关键步骤失败会终止流水线**，可选步骤失败会跳过继续。

#### prompts.py — Prompt 构建逻辑

**模块级**：
- 定位并加载 `prompts_data.json`（`sys.frozen` 判断 PyInstaller/开发环境，utf-8-sig 读取，失败抛 RuntimeError）
- 导出：
  - `STEP_SYSTEM_PROMPTS` — 9 步系统提示词
  - `STEP_PARAMS` — 11 组采样参数（含 chapter/chapter_polish）
  - `CHAPTER_SYSTEM_PROMPT` — 章节生成系统提示词
  - `CHAPTER_POLISH_PROMPT` — 章节润色提示词

**函数**：
- `_join(*parts) -> str` — 非空部分以空行拼接
- `build_step_user_prompt(step_name, step_description, user_concept, title, word_count, previous_context=None, genre_hint="", chapter_context=None) -> str` — 概念居中的用户提示词
- `_extract_summary(full_context) -> str` — 按 `===` 分节提取前 8 行、超 5000 字逐行截断

**System Prompt 结构**：
```
PERSONA + RULES + FORMAT + STEP_XXX
```
- PERSONA：角色设定（"你是网文设定架构师"）
- RULES：7 条铁律（禁止 AI 腔、情绪身体化、节奏短句等）
- FORMAT：输出格式要求（使用 `=== 板块名 ===` 分隔）
- STEP_XXX：具体步骤的指令

**User Prompt 结构**：
```
【核心概念】「用户输入的故事概念」
【作品标题】书名
【目标字数】500,000 字（约 142 章）
【类型标签】玄幻
【已生成的设定 —— 必须基于以下内容继续，保持一致性】
（前序步骤的输出摘要，压缩到 5000 字以内）
【当前任务】世界观构建 —— 物理法则、时代背景、地理、政治、人文
```

**上下文压缩算法**（`_extract_summary()`）：
1. 按行遍历，识别 `=== 板块名 ===` 分隔符
2. 每个板块保留前 8 行
3. 如果总长度超过 5000 字，逐行截断并添加 `[...已压缩，保持 token 预算]`

**Prompt 风格**：非常直白粗暴，使用大量脏话和口语化表达（如"别他妈写那种文笔优美但屁事没发生的东西"），这是刻意设计的——目的是让 AI 输出更有网感的内容，避免 AI 腔。

#### orchestrator.py — 流水线编排器

```python
class NovelGenerationEngine:
    def __init__(provider: BaseProvider)
    def on_step_complete(callback)
    def create_session(book_id, title, concept, word_count, mode="auto") -> GenerationSession
    def get_session(session_id)
    def get_session_by_book_id(book_id)
    def _prepare_step(session, step_num, step_key) -> (system_prompt, user_prompt, params)
    async def stream_pipeline(session) -> AsyncIterator[dict]
    async def execute_single_step(session, step_num) -> StepResult
    async def cleanup_expired_sessions()  # 2小时过期 + 1000会话上限
```

**生成流程**（`stream_pipeline`）：
1. `yield pipeline_start`；遍历 `PIPELINE_STEPS_DEF` 的 9 步
2. 已完成的步骤 → `yield step_skip` 跳过；否则置 RUNNING 并 `yield step_start`
3. `_prepare_step` 组装三要素：系统提示词、用户提示词（注入前序上下文摘要）、生成参数
4. 流式调用 `provider.stream_generate`，逐 token `yield {"type": "token", ...}` 并累积全文
5. 成功：置 COMPLETED、写入 `StepResult` 与 `context_log`、`yield step_complete`、触发回调
6. 异常：关键步骤 → 置 FAILED、`yield pipeline_error` 并终止；非关键 → 置 SKIPPED、`yield step_error` 并继续
7. 全部结束：`session.is_complete = True`，统计完成数，`yield pipeline_complete`

**SSE 事件类型**：
- `pipeline_start` — `{type, session_id}`
- `step_start` — `{type, step, name, description}`
- `step_skip` — 跳过已完成步骤
- `token` — `{type, step, token}` — 流式 token
- `step_complete` — `{type, step, result}`
- `step_error` — 可选步骤失败
- `pipeline_error` — 关键步骤失败，终止
- `pipeline_complete` — `{type, completed_steps, total_steps}`

1. `await init_db()` — 创建表

1. 请求体（provider / model / apiKey / apiBase）
2. 数据库中的激活 ModelConfig（apiKey 加密存储，decrypt 后使用）
3. 环境变量 / .env（DEEPSEEK_API_KEY、OPENAI_API_KEY、ANTHROPIC_API_KEY 等）
4. 按 provider 名补默认 Base URL

**序列化辅助**：
- `_dt(v)` — datetime → ISO 格式字符串
- `_book_to_dict(b)` — 书籍 → camelCase dict（含 `pipelineProgress` 计算为 `steps/9`）

- `_item_to_dict(i)` — 物品 → camelCase dict
- `_outline_to_dict(o)` — 大纲 → camelCase dict
- `_hook_to_dict(h)` — 伏笔 → camelCase dict
- `_truth_file_to_dict(t)` — 真相文件 → camelCase dict

## 7. 九步流水线状态机

```
PENDING → RUNNING → COMPLETED
                  → FAILED (关键步骤 → 终止流水线)
                  → SKIPPED (可选步骤 → 继续下一步)
```

**状态转换逻辑**（orchestrator.py）：
1. **PENDING → RUNNING**：流水线开始执行某一步时
2. **RUNNING → COMPLETED**：AI 成功返回结果
3. **RUNNING → FAILED**：AI 调用失败且是关键步骤
4. **RUNNING → SKIPPED**：AI 调用失败但是可选步骤

**上下文传递**：每一步的 `result_text` 会通过 `session.get_previous_context()` 传递给下一步，作为 AI 的输入上下文。这确保了设定的连贯性。

**会话清理**：
- `cleanup_expired_sessions()` — 2 小时过期 + 1000 会话上限
- `_periodic_session_cleanup()` — 每 30 分钟自动调用

### 10.2 仍存在的问题

2. **数据库迁移**：使用 `Base.metadata.create_all()` 创建表，没有迁移机制（如 Alembic）。修改模型定义时现有数据库不会自动更新。
3. **SSE 流取消机制**：用户关闭窗口后，后端检测到断开会停止生成（`request.is_disconnected()`），但已发起的 AI 调用可能仍在进行。

5. **`cors_origins` 硬编码**：只允许 `localhost:5173` 和 `127.0.0.1:5173`，实际运行时端口是动态的（但桌面应用同源，不影响）。
6. **`GenerationParams.extra` 未使用**：所有 provider 都忽略了它。
7. **`generation_records` 没有 relationship 回 books**：只有 ForeignKey，没有 relationship 定义。

## 15. 关键设计决策

1. **为什么用 SSE 而不是 WebSocket？** 九步流水线是单向流（服务器→客户端），SSE 更简单且天然支持断线重连。

2. **为什么 Prompt 用脏话风格？** 实测发现直白粗暴的指令能让 AI 输出更有"网感"的内容，避免 AI 腔（如"值得一提的是""总的来说"）。这是刻意的设计选择。

3. **为什么用 SQLite 而不是 PostgreSQL？** 桌面应用，单用户，SQLite 足够且无需额外安装数据库服务。

4. **为什么前端以编译产物交付？** 项目定位为桌面应用，前端源码未随仓库分发，仓库内仅包含编译后的静态文件（如需修改 UI 需按文档说明重新构建）。

5. **为什么 API Key 用 Fernet 加密？** 桌面应用需要持久化 API Key，明文存储有安全风险。Fernet 是对称加密，密钥存储在本地文件，无需用户记忆密码。同时 decrypt 做了明文兼容，确保旧数据不会报错。

6. **为什么 API 统一为 /api/v1/ 前缀？** 与编译后的 React 前端保持一致，前端硬编码了此前缀。

7. **为什么输出 camelCase？** 前端是 React/JS 生态，camelCase 更符合 JS 命名习惯。输入兼容 snake_case 是为了方便 Python 客户端和测试。

8. **为什么类型模板在章节生成时才注入？** 九步流水线的 prompts_data.json 是通用的，不区分类型。类型规则通过 `genre_rules_text()` 在章节生成时动态注入 user prompt，这样九步设定生成可以保持通用性，章节生成时再应用类型-specific 规则。

9. **为什么引擎缓存键包含 API Key 哈希？** 同一 provider/model 但不同 key（多账号切换）不能复用同一个 engine/provider 实例，否则会串号使用旧 key。

10. **为什么逐章提交数据库？** 长批次生成时进程中断/断线也不丢失已完成章节。
